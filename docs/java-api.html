API JAVA V1 · PRÉVERSION DÉVELOPPEUR

Des modules natifs.
Vos propres idées.

Créez de vrais mods Fabric qui s’intègrent au Companion : modules, réglages, événements, HUD, écrans et données de minage. Utilisez aussi Minecraft et Fabric directement.

Préparée pour 1.46.0-major-beta.3. Cette API n’est pas incluse dans la version stable 1.45.0. Installation, mise à jour et suppression d’un JAR : redémarrage obligatoire.

Tout le nécessaire, sans le code privé

Le SDK contient uniquement les interfaces publiques du package fr.minerite.companion.api. Le Companion installé fournit leur implémentation. Vous pouvez compiler une extension sans accéder aux sources du client.

  • SDK Java · Minecraft 26.2 ↓ · Sources des interfaces pour votre IDE
  • SDK Java · Minecraft 26.3 ↓ · Sources des interfaces pour votre IDE
  • Projet Gradle complet · Carnet Java ↓

Prérequis : JDK 25, Fabric Loader 0.19.5 ou plus récent ; Fabric API 0.161.0+26.2 pour Minecraft 26.2, ou 0.164.0+26.3 pour Minecraft 26.3. Utilisez le SDK correspondant à la version ciblée. La compatibilité avec les futures versions de Minecraft n’est pas garantie.

Le SDK est une dépendance de compilation, pas un mod à installer. Ne le placez pas dans mods/ et ne l’embarquez pas dans votre JAR.

Compiler votre première extension

  1. Décompressez le projet de départ et placez le SDK dans son dossier libs/.
  2. Choisissez minecraft_version=26.2 ou 26.3 dans gradle.properties.
  3. Exécutez gradlew.bat build sous Windows, ou ./gradlew build sous Linux/macOS.
  4. Placez le JAR de build/libs/ dans mods/, avec une version compatible de Companion et Fabric API, puis redémarrez le jeu.
  5. Ouvrez Extensions → Java. « Carnet Java » figure aussi dans les modules ; F8 ouvre son écran.

Pour lancer runClient depuis le projet, placez le JAR du Companion dans run/mods/. Avant publication, remplacez les identifiants, le package et les informations du projet.

Un point d’entrée Fabric dédié

L’identifiant Fabric officiel du client est minerite_companion ; CompanionApi.MOD_ID expose cette valeur. L’ancien identifiant est uniquement un alias de compatibilité pour les extensions déjà compilées. Utilisez le nouvel identifiant pour vos dépendances.

"entrypoints": {
  "minerite-companion": ["example.companion.ExampleAddon"]
},
"depends": {
  "minerite_companion": ">=1.46.0-major-beta.3",
  "minecraft": "26.2",
  "fabricloader": ">=0.19.5",
  "java": ">=25"
}

Avant l’entrée dans un monde, Minecraft n’a pas encore lié les composants des objets. Ne construisez pas d’ItemStack pour une icône dans initialize : utilisez Definition.item. Le constructeur historique acceptant un ItemStack reste présent pour la compatibilité binaire ; une pile personnalisée doit être créée lorsque les données du monde sont disponibles.

La classe implémente CompanionAddon. Companion appelle initialize(CompanionApi api) après le démarrage du client, sur le thread client. L’identifiant de l’extension provient du conteneur Fabric.

public final class ExampleAddon implements CompanionAddon {
    public void initialize(CompanionApi api) {
        var module = api.register(CompanionApi.Definition.item(
            "mining-notes", "Carnet", "Un module Java",
            "minecraft:writable_book", true));
        var visible = module.toggle("visible", "Afficher le HUD", "", true);
        module.hud(frame -> {
            if (!visible.get()) return;
            api.ui().panel(frame.graphics(), 240, 100, 190, 36, 0xDD15171C);
            api.ui().text(frame.graphics(), "Mon module", 250, 113,
                170, 1, api.ui().colors().text(), false);
        });
    }
}

Créer librement, sans modifier les modules existants

Une extension peut créer ses propres comportements, modules, écrans, rendus, ressources, raccourcis et services avec Minecraft, Fabric et Java. Les données exposées par Companion sont des copies ; aucun contrôleur public ne permet de modifier les réglages, d’activer, de remplacer ou de supprimer un module intégré ou appartenant à une autre extension.

Chaque module appartient à son extension. Appeler votre module session lui donne l’identifiant java:votre_extension:session : il ne remplace pas le module de session du Companion.

Les personnalisations visuelles restent autorisées : thèmes, couleurs, interfaces propres à l’extension et dispositions HUD. Utilisez les points d’entrée visuels prévus pour changer l’apparence ou la position des panneaux existants, sans toucher à leur fonctionnement.

Ce périmètre est le contrat de l’API et de publication, pas une isolation de Java. Un JAR Fabric peut techniquement utiliser la réflexion ou des mixins pour modifier le client. Une extension approuvée doit donc éviter les classes privées kiru.swing.* et ne pas détourner les modules du Companion. La revue des sources et du JAR reste nécessaire.

Modules, réglages et services

Déclarez les modules, réglages et actions pendant initialize. Les identifiants locaux font entre 2 et 48 caractères : lettres minuscules, chiffres, tirets ou traits de soulignement, avec une lettre au début. L’identifiant complet d’un module est java:identifiant_fabric:identifiant_module.

APIComportement
api.register(Definition)Crée un module intégré au hub : nom, description, icône ItemStack et activation par défaut. Jusqu’à 64 modules par extension. Utilisez Definition.item(id, nom, aide, "minecraft:writable_book", actif) pour une icône chargée au moment du rendu, sans créer d’objet au démarrage.
module.toggle(id, nom, aide, initial)Retourne un Setting<Boolean>.
module.number(id, nom, aide, initial, min, max)Retourne un Setting<Double>. Bornes finies, minimum strictement inférieur au maximum ; valeurs hors limites et NaN refusées.
module.text(id, nom, aide, initial)Retourne un Setting<String>, limité à 256 caractères. Jusqu’à 64 réglages par module.
setting.get() / set(valeur)Lecture immédiate, validation et sauvegarde automatique. Les réglages apparaissent dans la fiche du module.
module.action(nom, aide, callback)Ajoute un bouton dans sa fiche. Le callback est exécuté uniquement si le module est actif.
api.snapshot(Data)Copie JSON indépendante : PLAYER, WORLD, TARGET, HELD, INVENTORY, SESSION ou COUNTERS. Vérifiez available. Champs des instantanés ; en Java, les tableaux JSON sont indexés à partir de zéro.
api.client()Accès natif à Minecraft pour vos propres comportements, écrans et rendus.
api.configDirectory()Dossier réservé à l’extension sous config/minerite-companion/java-addons/. Les réglages gérés sont conservés dans le fichier commun settings.json.
api.execute(callback)Planifie une tâche sur le thread client depuis un autre thread. Vérifiez module.active() avant d’appliquer un résultat lié à un module.
module.notify(message)Message local identifié, limité à un toutes les 250 ms par module, uniquement en jeu et si actif.
module.command(commande)Retourne vrai si une commande a été envoyée. Limite commune aux modules Java : une par seconde, 256 caractères maximum. Respectez les règles du serveur.

Événements et abonnements

on, every, hud, key, onEnable, onDisable et onSettingChanged retournent un Subscription : appelez close() sur le thread client pour retirer l’abonnement. Jusqu’à 128 abonnements par liste.

module.on(CompanionApi.Event.CHAT, json -> {
    String message = json.getAsString();
});
module.every(20, () -> {
    var session = api.snapshot(CompanionApi.Data.SESSION);
});
module.key("key.keyboard.f8", () -> ouvrirEcran());
module.onSettingChanged(setting -> actualiser(setting.id()));

Événements disponibles : TICK, JOIN, LEAVE, CHAT, ACTIONBAR, INVENTORY_CHANGED, HELD_ITEM_CHANGED, BLOCK_MINED, SESSION_CHANGED, COUNTERS_CHANGED. TICK reçoit JSON null ; JOIN un instantané du monde ; LEAVE un objet vide ; CHAT et ACTIONBAR une chaîne ; BLOCK_MINED des coordonnées x, y, z. Les autres événements reçoivent l’instantané correspondant.

Les changements de données sont comparés toutes les dix ticks, uniquement lorsque des abonnements les utilisent. Un bloc miné est un bloc comptabilisé par le suivi local, pas une statistique serveur certifiée. Les raccourcis sont déclenchés au nouvel appui, en jeu sans écran ouvert ; ils ne bloquent pas les touches vanilla.

HUD, écrans et apparence

module.hud(frame -> ...) fournit le GuiGraphicsExtractor natif et les dimensions de l’interface. Le HUD géré est dessiné en jeu, hors menus et lorsque le HUD est visible. Utilisez api.ui().text(...) pour la typographie du Companion, panel(...) pour ses surfaces et colors() pour ses couleurs courantes.

module.openScreen(() -> votreScreen) accepte n’importe quel écran Minecraft. Pour réutiliser les composants du Companion, api.ui().settingsScreen(parent, titre, sousTitre, page -> ...) fournit group, info, action, toggle, number et text, avec navigation et défilement intégrés. Les fonctions de contenu sont rappelées à chaque reconstruction : ne réenregistrez pas vos modules à cet endroit.

module.action("Réglages", "Ouvrir mon écran", () -> {
    Screen parent = api.client().gui.screen();
    module.openScreen(() -> api.ui().settingsScreen(
        parent, "Mon module", "Mes réglages", page -> {
            page.group("Affichage");
            page.toggle("Visible", "", visible::get,
                () -> visible.set(!visible.get()));
        }));
});

module.appearance(new Appearance(theme, layout, cardStyle, accent)) applique un préréglage tant que le module est actif. Chaque champ peut être null pour conserver la valeur précédente. Passez null à appearance pour retirer le préréglage. Les choix personnels enregistrés ne sont pas remplacés.

  • Thèmes : OBSIDIAN, GRAPHITE, MIDNIGHT, PAPER, SLATE, AMETHYST, MOCHA, FOREST, ROSE, ABYSS.
  • Dispositions : STANDARD, COMPACT, FOCUS, LIST, GALLERY, INSPECTOR, RAIL, WIDE.
  • Surfaces : SOLID, GLASS, OUTLINE, TEXT, LINE, ACCENT, GRADIENT. Accent : six chiffres hexadécimaux, avec ou sans #.

Une disposition HUD sans modifier les modules

module.hudLayout(Map.of(
    CompanionApi.HudWidget.FPS,
    new CompanionApi.HudPlacement(0.02, 0.05, 1.0),
    CompanionApi.HudWidget.COORDINATES,
    new CompanionApi.HudPlacement(0.02, 0.15, 0.9)
));

HudPlacement(x, y, scale) utilise des coordonnées normalisées entre 0 et 1 dans l’espace restant après la taille du panneau ; l’échelle va de 0,4 à 2,5. Les valeurs hors limites et non finies sont refusées. Cette disposition ne change ni la visibilité, ni les données, ni la logique du module. Elle s’applique uniquement tant que son module d’extension est actif.

api.ui().hudLayout() retourne une copie non modifiable des positions effectives ; un panneau en position automatique n’a pas d’entrée. Passez Map.of() à module.hudLayout pour retirer vos remplacements. La carte fournie est copiée. Si plusieurs modules actifs ciblent le même panneau, le dernier enregistré prend le dessus. L’éditeur HUD affiche et modifie la disposition personnelle, sans les remplacements temporaires ; son fichier n’est pas écrasé par l’extension.

Panneaux disponibles : SESSION, OBJECTIVES, ALERTS, FPS, COORDINATES, INVENTORY, CRAFT, BALANCE, GEMS, PRESTIGE. Le projet de départ inclut un réglage de démonstration désactivé par défaut.

Ces préréglages utilisent les styles existants du Companion. Pour un rendu entièrement nouveau, créez vos propres écrans et composants natifs ; l’API v1 ne remplace pas automatiquement le moteur de disposition du hub.

Un cycle de vie explicite

enabled() indique le choix du joueur ; active() tient aussi compte des erreurs et du contrôle administratif des extensions. status() donne un diagnostic lisible. À la désactivation, Companion arrête ses callbacks gérés, minuteries, raccourcis et HUD, ferme l’écran directement ouvert par le module s’il est encore affiché, puis appelle onDisable. Les réglages sont conservés.

onEnable est appelé à l’activation ; onDisable après l’arrêt et à la fermeture du client. Libérez vos ressources dans ce dernier. Une exception dans un callback géré arrête uniquement le module concerné ; son erreur est journalisée et visible dans sa fiche. Corrigez le problème et redémarrez pour réessayer.

Java est du code natif, sans bac à sable. Les mixins, bibliothèques, événements Fabric et threads créés directement par une extension ne sont pas déchargés par Companion. Ils doivent vérifier l’état du module et prévoir leur propre nettoyage. Une désactivation administrative ne peut pas empêcher un JAR arbitraire de s’exécuter hors de l’API.

Toutes les mutations de l’API et lectures d’instantanés se font sur le thread client. Déportez les traitements lents ; repassez par api.execute pour appliquer leurs résultats. Une extension Java peut accéder aux fichiers et au réseau comme n’importe quel autre mod : n’installez que du code de confiance.

Tester et proposer une extension

Dans cette préversion, les JAR Java s’installent manuellement dans mods/. Ils apparaissent ensuite dans la section Java du Companion. L’installation à chaud du catalogue concerne Lua ; un parcours de téléchargement approuvé avec redémarrage sera nécessaire pour les JAR Java.

Pour proposer votre projet, fournissez le code source de l’extension, sa licence, ses dépendances, le JAR reproductible, les versions prises en charge et la liste des accès réseau, fichiers et mixins. Une soumission ne vaut pas approbation. Le code privé du Companion n’est jamais nécessaire pour cette revue.

Testez au minimum l’installation, l’activation, la désactivation en jeu, les reconnexions, les erreurs, l’absence de monde et la fermeture du jeu. Compilez et testez séparément pour chaque version de Minecraft ciblée. Le SDK v1 est encore une préversion ; les changements incompatibles seront signalés avant sa stabilisation.
