Un premier module en quelques minutes

Télécharger le projet « Carnet de session » ↓ — un exemple complet avec HUD, réglages, stockage et écran ouvert avec K.

  1. Activez le mode développeur dans les réglages du Companion.
  2. Décompressez les fichiers dans config/minerite-companion/addons/development/session-notebook/. Le dossier doit contenir directement addon.json et main.lua.
  3. Ouvrez Extensions → Développer → Recharger les projets locaux.
  4. Modifiez le script et rechargez les projets pour appliquer vos changements immédiatement.

Les projets locaux ne sont pas approuvés. Ils s’arrêtent lorsque vous désactivez le mode développeur. Un identifiant déjà installé depuis le catalogue ne peut pas être remplacé par un projet local.

Le manifeste : addon.json

{
  "api": 1,
  "id": "mon-module",
  "name": "Mon module",
  "author": "Votre pseudo",
  "version": "1.0.0",
  "description": "Un module créé avec l’API Companion.",
  "minecraft": ["26.2", "26.3"],
  "permissions": ["session", "hud"]
}

Le script : main.lua

local module = companion.module {
    id = "compteur",
    name = "Mon compteur de blocs"
}

module:setting {
    id = "visible", name = "Afficher le compteur",
    type = "boolean", default = true
}

local blocs = 0
module:every(20, function()
    blocs = companion.session().blocks or 0
end)

module:hud(function(draw)
    if not module:get("visible") then return end
    draw:panel(12, 180, 190, 36, "DD15171C")
    draw:text(22, 193, "Blocs : " .. blocs, "E7B35A")
end)

Utilisez un identifiant différent dans le manifeste et le nom du dossier pour publier votre propre extension ; leurs valeurs doivent correspondre. Un identifiant de module est local à son extension. Les identifiants comportent 2 à 48 caractères : lettres minuscules, chiffres, tiret ou trait de soulignement, avec une lettre au début.

Référence de l’API v1

La syntaxe companion.fonction() appelle l’API générale. La syntaxe module:methode() appelle une méthode sur un module. Déclarez vos modules et leurs callbacks au chargement du script ; leur enregistrement est ensuite fermé.

FonctionUsage
companion.module{ id, name, description?, enabled? }Crée un module ; actif par défaut. Le joueur peut désactiver l’extension entière ou chaque module séparément.
module:setting{ id, name, help?, type, default, min?, max? }Ajoute un réglage persistant : boolean, number ou text. Les nombres ont des bornes, 0 à 100 par défaut. Le texte est limité à 240 caractères.
module:get("id")Lit un réglage. Ses modifications sont accessibles immédiatement.
module:store("cle", valeur)
module:store("cle")		Écrit ou lit une valeur locale persistante : texte, nombre, booléen ou nil. 64 clés par module. Aucun accès arbitraire aux fichiers.
module:on("evenement", function(value) … end)Événements : enable, disable, tick, join, leave, chat, actionbar, inventory_changed, held_item_changed, session_changed, counters_changed, setting_changed.
module:every(ticks, callback)Minuterie de 1 à 72 000 ticks client. Environ 20 ticks par seconde, selon les performances du jeu. Arrêtée avec le module.
module:bind("key.keyboard.k", callback)Callback au nouvel appui, uniquement en jeu lorsqu’aucun écran n’est ouvert. La touche ne remplace pas les raccourcis vanilla ; évitez les conflits.
module:hud(function(draw) … end)Dessine en jeu. draw.width et draw.height sont les dimensions de l’interface, pas les pixels physiques de l’écran.
module:open(titre, function(ui) … end)Ouvre un écran avec les composants et le défilement du Companion. Ajoutez ui:label(texte, aide?) et ui:button(texte, callback). Le contenu est construit à l’ouverture.
companion.notify(texte)Affiche un message local identifié par le nom de l’extension.
companion.command("spawn")Envoie une commande au serveur, avec la permission commands. Limite globale d’une commande par seconde ; un dépassement met l’extension en erreur.
companion.contains(texte, recherche)Recherche littérale sans distinction de casse ; n’interprète pas les motifs Lua.
companion.time()Heure Unix en secondes. companion.api_version expose la version numérique de l’API.

Dessiner sur le HUD

draw:text(x, y, texte, couleur?)
draw:panel(x, y, largeur, hauteur, couleur?)
draw:rect(x, y, largeur, hauteur, couleur?)
draw:bar(x, y, largeur, hauteur, fraction, couleur?, fond?)
draw:item(x, y, "minecraft:netherite_ingot")

Les couleurs sont des textes hexadécimaux RRGGBB ou AARRGGBB. La progression d’une barre est comprise entre 0 et 1. Les icônes utilisent les objets et les ressources actifs de Minecraft. L’API v1 ne charge pas de modèle ou de police arbitraire depuis une archive.

Événements et cycle de vie

tick et les minuteries reçoivent le compteur de ticks de l’extension. chat et actionbar reçoivent un texte ; setting_changed reçoit l’identifiant du réglage. Les événements de données reçoivent le même instantané que les fonctions ci-dessous. Les changements d’inventaire, d’objet tenu, de session et de compteurs sont comparés toutes les dix ticks. enable et disable n’ont pas de charge utile.

À la désactivation : callbacks, minuteries, touches et HUD cessent de s’exécuter ; un écran appartenant à l’extension se ferme. Les réglages et le stockage sont conservés. Une erreur arrête l’extension et son diagnostic apparaît dans sa fiche.

Lire les données disponibles

Les fonctions retournent des copies Lua des données observées par le client. Elles ne fournissent ni historique serveur caché ni accès à une API Minerite. Vérifiez toujours available avant d’utiliser un instantané hors jeu.

Fonction / permissionChamps
companion.player() · playername, health, max_health, hunger, armour, level, xp_progress, x, y, z, yaw, pitch, fps, held_item
companion.world() · playerserver, singleplayer
companion.target() · playerheld_item ; désigne actuellement l’objet tenu, pas le bloc visé.
companion.inventory() · inventoryslots : liste Lua indexée à partir de 1. Chaque ligne porte le numéro de slot Minecraft dans slot.
Objetempty, id, name, count, damage, max_damage, model?, lore. Le nom et la description conservent les glyphes du serveur.
companion.session() · sessionactive, started, elapsed_ms, paused, blocks, earnings, drops. Les gains restent un texte décimal pour éviter la perte de précision. Les drops contiennent name, count.
companion.counters() · countersmoney?, gems?, prestige? : textes reçus depuis les barres du serveur. Un champ absent signifie que sa valeur n’a pas été reçue.

Les permissions disponibles sont player, inventory, session, counters, chat, commands, appearance, hud, screens, keys. Elles sont déclarées dans le manifeste et présentées au joueur avant l’installation. Un appel sans permission arrête l’extension.

Créer des thèmes et des dispositions

module:appearance {
    theme = "MIDNIGHT",
    accent = "72A7F7",
    layout = "COMPACT",
    card_style = "GLASS"
}

Requiert la permission appearance. Le préréglage s’applique tant que le module est actif ; les préférences personnelles restent conservées. Plusieurs préréglages actifs sont appliqués dans leur ordre de chargement ; le dernier prend priorité sur les champs qu’il définit.

  • Thèmes : OBSIDIAN, GRAPHITE, MIDNIGHT, PAPER, SLATE, AMETHYST, MOCHA, FOREST, ROSE, ABYSS.
  • Dispositions : STANDARD, COMPACT, FOCUS, LIST, GALLERY, INSPECTOR, RAIL, WIDE.
  • Cartes : SOLID, GLASS, OUTLINE, TEXT, LINE, ACCENT, GRADIENT.

Il s’agit de préréglages pour les interfaces existantes. Les modules peuvent créer leurs propres écrans et HUD avec l’API ; les mises en page arbitraires des écrans internes du Companion ne sont pas exposées dans la v1.

Faire approuver et publier une extension

  1. Préparez une archive ZIP contenant directement addon.json, main.lua et, si besoin, README.md. Aucun JAR ou exécutable n’est accepté.
  2. Ouvrez une demande de publication avec votre code source, une description, les permissions utilisées et les versions de Minecraft testées.
  3. La version est examinée avant publication. L’approbation concerne une archive précise, identifiée par son SHA-256.
  4. Après approbation, elle apparaît dans le catalogue du jeu. Chaque mise à jour repasse par la même vérification.

Le catalogue indique la compatibilité, la version, l’auteur et les permissions. L’installation vérifie la taille, l’empreinte et le manifeste avant activation. Si une nouvelle version échoue au chargement, la version précédente est restaurée. Une version révoquée est arrêtée après réception du catalogue actualisé, vérifié environ chaque minute en ligne.

Hors ligne, le mod conserve la dernière liste connue. Un retrait d’approbation ne peut pas être reçu sans connexion. Les projets locaux utilisent un circuit distinct réservé au mode développeur.

Cadre technique

Lua 5.2 via LuaJ, avec une sélection limitée des bibliothèques de base. Les accès Java, réseau, processus, fichiers, chargement de code, débogage et coroutines ne sont pas exposés. math, les boucles et les tables Lua sont disponibles ; la bibliothèque string expose uniquement byte, char, len, lower, upper et sub. Les fonctions de table standard ne sont pas exposées : utilisez les indices et l’opérateur #.

Limites v1 : 32 extensions installées ; 8 modules par extension ; 32 réglages, 32 callbacks, 16 minuteries et 8 raccourcis par module ; 128 opérations HUD par rendu d’extension ; 64 lignes par écran ; script limité à 64 Kio et archive à 512 Kio. Les callbacks disposent d’un budget d’instructions et d’une limite de profondeur. Ils doivent rester courts ; évitez de recalculer vos données à chaque rendu.

Ces limites réduisent les erreurs et les abus, mais ne constituent pas une isolation mémoire complète d’un programme natif. La revue des sources reste indispensable. Les mixins, nouveaux registres Minecraft et bibliothèques Java externes ne sont pas pris en charge : ils demanderaient un mod Fabric classique avec redémarrage.

Moteur : LuaJ, licence MIT. L’API est versionnée indépendamment du Companion ; une archive demandant une version inconnue est refusée.
